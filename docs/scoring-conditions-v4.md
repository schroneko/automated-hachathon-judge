# Condition-based judging v4

2026年10月18日、固定SHAのソース全文で15例を検証しました。記録は [JSON](scoring-conditions-v4.json) に保存しています。各例のSHA、全文hash、20条件の確率・真偽、診断、request IDを記録しました。

## Method

Decisions APIの `gpt-6-luna` へ20個の独立したpredicateと攻撃判定を送り、確率0.8以上を条件確認済みとします。各軸は2点から連続して確認できた最高段階を採用します。上位だけ成立した条件は点数へ繰り上げず、要確認を保持します。確率の平均、四捨五入、目標点への調整は行いません。0.8は判定の閾値であり、採点精度80%の保証ではありません。

同じSHA・同じ全文を `gpt-6.1-sol` へ送り、固定点と条件判定への説明を生成します。実作品3件の理由はmedium、他12例はlowです。各例でDecisionsを2回呼び、条件確率・真偽・得点が一致しました。理由生成後も点数・攻撃判定・SHA・hash・条件・確率・閾値・基準の版を保存境界で固定します。

## Review and calibration limits

`disconnected-model-name` は独創性6点条件が0.72で未達、8点条件が0.94で成立しました。これはモデル回答の不整合です。コードは4点で停止し、要確認を維持し、Solも不整合を説明しました。検証の成功は宣言した期待条件と保存・採点ガードの成功を意味し、すべてのモデル判定が正しいという意味ではありません。他の要確認も自動解除しません。

校正中に、UXの入口で自動起動するcontent scriptの例示が抜けていた点と、完成した主導線を未完成の別統合と混同しうる文言を修正しました。閾値は変えていません。ロボット作品の独創性は本音と外向き動作の分離、非公開情報の分離、反復防止を実backendのテストで確認でき、旧期待値の上限8点に根拠がなかったため許容範囲を見直しました。合計点を正解として固定していません。

15例は意図的に選んだ静的ソース検証です。30チームの点数分布、順位の妥当性、実機動作、実際の使い心地を保証しません。API拒否・取得失敗・容量超過を未実装0点に置き換えず停止します。過去のv2・v3結果は当時の版として保持し、新しい採点にv4を適用します。
